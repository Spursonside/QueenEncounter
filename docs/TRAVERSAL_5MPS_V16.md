## 실시간 화면 점검

렌더링을 켠 경사 출발에서도 50.025m를 11.246초에 완주했고 순항 속도는 5.000m/s였다. `viewer_hills.json`과 CSV를 같은 독립 감사로 확인했다. 약 2.8초의 발 들림 자세와 약 11.3초의 완료 자세를 화면에서 점검했다. 인접 다리 궤적이 분리되고 큰 발 들림이 보였으며 최종 화면에는 조명 재빌드 경고가 없었다. 영상은 촬영하지 않았다. 시각 기록의 범위는 `visual_qa.json`에 명시했다.

## 구현 방식

V15 관절 모터 실험에서는 목표 속도에서 접지와 자세가 무너졌다. 사용자가 방법론 변경을 허용한 뒤, 정상 6족 이동을 **절차적 보행 + 지형 IK + 충돌 검사가 있는 몸체 이동**으로 분리했다. 기존 `APhysicsQueen`, V14 정책과 V15 실패 기록은 보존했다.

**이 버전은 머신러닝 결과가 아니다.** 몸체 추진을 관절 힘으로 만들어내는 물리 시뮬레이션도 아니다. 게임의 이동 제어기가 몸체를 이동시키고, 다리는 그 이동을 지탱하는 자세를 절차적으로 계산한다. 접지 이탈이 거의 0인 것은 마찰 학습의 성과가 아니라 월드 좌표 발 고정의 결과다.

ARC Raiders 퀸을 목표로 한 자체 기본 도형 프로토타입이다. 원작 모델·애니메이션·소스 코드를 사용하지 않았으며, 원작의 보행 알고리즘을 재현했다고 주장하지 않는다.

## 보행 구성

- 몸체: 목표 5m/s, 가속도 2m/s². 실제 충돌 sweep을 사용하며 장애물을 통과하지 않는다.
- 발 순서: 대각선 두 발씩 세 그룹. 보행 주기 1.65초, 각 발이 공중에 있는 시간 약 0.462초. 최대 두 발이 공중에 있다.
- 보폭: 정속 구간의 한 발 재착지 간 전진 거리는 약 8.25m. 가속 전환에서 더 큰 발 이동이 나올 수 있으므로 원자료에 최댓값을 기록한다. 몸체 이동 거리와 발 이동 거리를 구분한다.
- 접지: 디딘 발의 월드 좌표를 유지한다. Sphere를 굴려 추진하지 않는다. 경사면 법선 방향으로 반지름만큼 띄워 구형 발을 배치한다.
- 스윙: 전후 궤적은 5차 보간, 높이는 sin² 곡선. 시작과 착지에서 속도를 부드럽게 줄인다. 경로의 지면을 샘플링해 장애물 여유를 확보한다.
- IK: 고정 길이 링크를 코사인 법칙으로 연결한다. 다리를 늘려서 목표점을 맞추지 않으며 도달 범위를 넘으면 실패 처리한다.
- 몸체: 지면 위 약 7m 유지, 지면 기울기의 일부를 반영하고 높이·회전을 보간한다. 작은 수직 움직임을 더해 완전히 고정된 몸통을 피한다.
- 지지: 접지한 발의 수평 지지 다각형 안에 몸체 중심이 있는지 검사한다. 이것은 수평 투영 기반의 기하학 검사이며 동역학적 안정성 증명은 아니다.
- 간섭: 다른 다리의 링크 사이를 두꺼운 캡슐로 감싸 최소 간격을 검사한다. 장갑·관절 크기를 포함해 다리가 겹치는 후보를 실패 처리한다.

앞·뒤 발을 전후로 벌리고 가운데 발을 바깥에 배치한 이유는 큰 보폭에서 인접 다리의 궤적 교차를 피하기 위해서다. 단순히 다리를 가늘게 줄여 간섭을 숨기지 않았다. 관절은 장착부·힙·무릎·종아리·발목의 다섯 위치로 나뉘며, 이번 제어기는 이들의 자세를 IK로 결정한다.

## 검증과 재현

최종 원자료는 `LearningRuns/v16_release/verification.json`이다. 각 케이스에 JSON 요약, 0.1초 간격 CSV, UE 로그가 있다. 검증 스크립트는 CSV의 거리 차이/시간 차이로 순항 속도를 다시 계산하고 UE가 보고한 통과 여부와 독립적으로 비교한다. 동시에 실행하는 시뮬레이션은 두 개다.

검증 기준은 50m 완주, 10m 이후 5초 이상 측정, 4.5~5.5m/s 비중 80% 이상, 각 다리 3회 이상 재착지, 도달 오차 1cm 이하, 발 지면 관통 5cm 이하, 접지 위치 이탈 1cm 이하, 공중 발 2개 이하이다. 높이 평균은 7m±0.5m, 높이 표준편차는 0.3m 이하, 몸체 기울기는 20° 이하이며 지지 영역 이탈·다리 간섭은 허용하지 않는다.

```powershell
# 실제 시간으로 50m 보행 반복. 완료 화면 3초 후 다시 시작한다.
.\Scripts\ReplayTraversal.ps1
# 경사에서 출발하는 경로
.\Scripts\ReplayTraversal.ps1 -Hills
# 새로운 이름을 사용해야 기존 기록을 덮어쓰지 않는다.
python .\Scripts\VerifyTraversal.py --run v16_my_check --workers 2
```

기존 `ReplayStrideGait.ps1`는 느리지만 보존한 V14 물리 보행이다. 새 5m/s 보행은 반드시 `ReplayTraversal.ps1`로 실행한다. 기존 패키지 실행 파일에 새 보행이 포함되었다고 간주하지 않는다. 이번 검증은 설치된 UE 에디터의 게임 실행 모드에서 수행했다.

## 이번 결과의 범위

이번 목표는 **정상 6족의 50m 직진 보행**이다. 특정 출발점과 방향에서 절차적 노이즈 Landscape를 검증했다. 모든 지형·급격한 방향 전환·계단·이동 플랫폼에서 작동한다는 의미는 아니다. 완료 시점에는 검증을 멈추므로 별도의 자연스러운 감속·정지 동작은 구현하지 않았다.

다리 파괴 후 Chaos 반응과 플레이어 사격은 기존 물리 모드에 보존되어 있다. 새 `ATraversalQueen`에 파괴·전투·결손 보행을 통합한 상태는 아니다. 다음 통합에서는 정상 이동의 IK 제어에서 파괴 순간의 물리 제어로 전환하는 처리가 필요하다.

포트폴리오에서는 “학습 기반 제어의 실패 원인을 측정하고, 사용자 경험에 필요한 속도·보폭·접지를 만족시키도록 제어 방식을 바꾸었으며, 시각 점검에서 발견한 다리 간섭을 회귀 검증 항목으로 추가했다”는 문제 해결 과정으로 설명할 수 있다.
