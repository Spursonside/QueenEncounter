# V11: Isaac Lab 평가 개념을 참고한 물리 보행

## 구현 범위

NVIDIA Isaac Lab Spot의 `air_time`, `foot_clearance`, `gait`, `foot_slip`, action smoothness 개념을 참고했다.
원본 코드 복사나 Isaac Lab 런타임 연동이 아닌 **UE 5.8.2 Chaos + 기존 Gaussian 진화 탐색** 구현이다. PPO/신경망 강화학습으로 표현하면 안 된다.

참고 소스: https://github.com/isaac-sim/IsaacLab/blob/release/3.0.0-beta2/source/isaaclab_tasks/isaaclab_tasks/manager_based/locomotion/velocity/config/spot/flat_env_cfg.py

- 구형 충돌 발과 동마찰 3 / 정마찰 4 / Max 결합을 유지했다.
- 여섯 다리를 0→4→2→3→1→5 순서로 움직이는 wave gait를 사용한다. 이동 구간 80%, 착지 여유 구간 20%다.
- 지지 발의 목표를 월드 좌표에 유지하고, 이동 발은 지형 ray로 찾은 착지점까지 위로 볼록한 궤적을 따른다.
- 순운동학/수치 IK로 기부·엉덩이·무릎 목표 각도를 계산한다. 종아리와 발목 모터는 중립을 지지한다. 모두 관절 제한과 유한 토크를 유지한다.
- 보행 중 실제 몸체나 발의 위치를 직접 설정하지 않는다. 계산한 목표 각도를 모터에 전달하고 실제 움직임은 중력·관절 힘·접촉에서 나온다.
- 목표 몸체 높이는 7m다. 실제 높이는 물리 결과이며 강제로 고정하지 않는다.
- 기존 관절별 자유 진동 대신 **다리 교대 시간, 보폭, 발 높이, 관절 강성** 네 변수를 학습한다. 저장 배열은 기존 94개 슬롯을 유지하지만 활성 인덱스는 0,1,2,37뿐이다.
- 발목 중립 복원 모터와 발의 각 감쇠를 강화했다.

## 평가와 단계 통과

발 접촉은 지형과 구형 발의 거리를 사용하는 근접 추정이다. 실제 접촉 힘 센서가 아니다. 4cm 이내에서 접촉, 접촉 중 8cm까지 유지하는 히스테리시스를 적용한다.

유효 걸음은 사전 접지 → 예정된 이동 구간에 이륙 → 0.15초 이상 공중 체류 및 25cm 이상 여유 높이 → 재접지로 판정한다. 이동 단계에서는 발의 수평 이동도 25cm 이상이어야 한다. 정지 상태나 구르기만으로는 걸음을 얻지 못한다.

점수에는 유효 걸음, 예정된 보행 단계와 접지 상태의 일치율, **접지 중 발 중심 속도와 발 각속도 벌점**을 추가했다. 접점 속도만 사용하면 순수 구르기를 놓치므로 발 중심과 회전을 별도로 평가한다. 기존 전진·속도·높이·몸체 회전 평가도 유지한다.

부모가 되려면 물리 실패가 없어야 하고, 20초 이상 평가, 직립 비율 90% 이상, 접지 발 중심 속도 평균 0.30m/s 이하, 발 각속도 평균 0.60rad/s 이하, 보행 일치율 75% 이상, 살아 있는 모든 다리에서 유효 걸음 1회 이상을 충족해야 한다.

- 단계 0: 제자리 발 들기. 앞뒤 이동 절댓값 2m 미만.
- 단계 1: 위 조건 + 전방 5m 이상.
- 단계 2: 위 조건 + 전방 15m 이상.
- 단계 3: 위 조건 + 전방 50m 이상.

점수가 높아도 단계 기준을 못 맞추면 계승하지 않는다. 부모가 없으면 실패 정책을 버리고 새 집단을 만든다. `TrainGaitCurriculum.ps1`은 통과 개체가 없으면 상위 단계로 진행하지 않는다. 수동 초기 정책도 `eligible_parent`가 거짓이면 거부한다.

## 실제 검증

- Editor Development 빌드 성공.
- `Queen.Learning.GaitStageGate`, `Queen.Learning.StrictCompletionParents` 자동 테스트 성공. 정지·구르기·미끄러짐·전복·단계 거리 미달과 물리 실패의 탈락을 확인했다.
- 제자리 단계: 4세대 × 8개체, 개체당 60초. 32개체 중 6개체 통과(동일 정책 재평가 포함).
- 이동 단계: 4세대 × 8개체, 개체당 최대 150초. 32개체 중 단계 통과 0개체. 물리 실패 개체는 조기 종료한다.
- `audit_gait.py`가 원본 후보 JSON으로 합격 기준을 독립 재계산하고 모든 부모 ID를 대조했다. 두 실행 모두 위반 0건.
- 50m 최종 합격은 0건이다. 이동 단계가 통과하지 않아 15m/50m 상위 단계 학습은 시작하지 않았다.

### 제자리 보행 독립 재생

`v11_stage0_train01/candidate_0003_04.json`을 다시 실행했다.

- 실제 60.016초, 유효 걸음 19회, 다리별 [4, 3, 3, 3, 3, 3].
- 접지 발 중심 속도 0.271m/s, 접지 발 각속도 0.325rad/s.
- 평균 높이 6.709m, 평균 기울기 1.022°.
- 전방 이동 -0.760m. **제자리 발 들기 검증이며 이동 완주 영상이 아니다.**
- 실제 프레임 601장, 10fps. Videos/22-wave-gait-lift-and-land.mp4.
- 재생 HUD 기본 총 세대 수 48을 영상 자막에서 실제 평가한 4세대로 정정했다.

### 이동 후보 선택

직립 비율 95% 이상, 물리 실패 없음, 전방 5m 이상인 후보 중 접지 발 중심 속도가 가장 낮은 `candidate_0001_02.json`을 영상용으로 선택했다. **영상 선택은 부모 자격과 별개다.**

- 평가 150.007초, 전방 19.946m, 유효 걸음 35회.
- 접지 발 중심 속도 0.390m/s로 기준 0.30을 초과했다. 부모 사용 불가.
- 거리만 가장 큰 기록을 보행 성공으로 취급하지 않는다. 전복/물리 폭주에 따른 큰 변위가 원본 데이터에 포함된다.

## 재현

```powershell
.\Scripts\TrainGaitCurriculum.ps1 -Generations 4 -Population 8
# 개별 단계
.\Scripts\TrainPhysics.ps1 -Terrain -Stage 0 -Generations 4 -Population 8 -Episode 60 -Sigma 0.5 -RunName new_stage0
python .\Scripts\audit_gait.py .\LearningRuns\new_stage0
```

새 정책은 `controller_version=v11_wave_ik`다. 이전 CPG 정책은 의미가 달라 기본 로더가 거부한다. 예전 정책을 진단할 때는 `-QueenLegacyGait`를 명시해야 하며, 당시 리그와 동일한 재현을 자동 보장하지 않는다.

## 남은 한계

접지 중 미끄러짐이 남아 있으며, 원작 퀸의 걸음걸이를 완전히 재현한 상태가 아니다. 관절 궤적과 보상 구조를 바꿔 실제 발 들기/착지를 얻은 단계다. 발 높이는 지형과 관절 순응에 따라 목표 궤적과 차이가 있다. 다른 지형 seed나 다리 파괴 상태의 이번 보행 정책은 아직 검증하지 않았다.

## 독립 이동 재검증: 재현성 문제 발견

병렬 후보 평가에서 자세를 유지한 이동 기록은 독립 재생에서 재현되지 않았다. 다음 세 후보는 모두 물리 실패로 종료됐다. 아래 전방 변위에는 실패 중 급격한 밀림/폭주가 포함될 수 있으므로 보행 성과로 사용하지 않는다.

| 실행 | 종료 시간 | 유효 발 들기/착지 | 실패 |
|---|---:|---:|---|
| v11_walk_replay | 38.183s | 4 | True |
| v11_verify_candidate_0001_06 | 142.693s | 42 | True |
| v11_verify_candidate_0003_07 | 119.494s | 42 | True |

확인된 성공 범위는 제자리 발 들기/재착지다. 이동 단계는 통과 0이며, 병렬 평가에서 얻은 19.95m 또는 33.51m를 재현 검증된 보행 거리로 표현하면 안 된다. 접지 오차에 따른 제어 안정성과 병렬/단독 실행 재현성 개선이 필요하다. 실패 영상은 Videos/23-wave-gait-movement-failed.mp4에 전 구간을 보존한다.
